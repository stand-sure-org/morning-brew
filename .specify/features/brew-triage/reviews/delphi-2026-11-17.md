## Key evidence the panel produced (verified on this machine, read-only)

1. **Upgrade closure is bidirectional.** `brew upgrade aws-c-auth --dry-run` → also upgrades dependents aws-c-s3, awscli; `brew upgrade awscli` pulls its deps. Source: `upgrade.rb:300-307`. A pinned outdated dep makes dependents uninstallable (`formula_installer.rb:488-512`); a pinned broken dependent is not repaired (`upgrade.rb:445-455`).
2. **`brew services` under-reports live services.** vector and nats-server show `none` but run from user LaunchAgents (`com.logshipping.vector`, `anderson.nats-server`); vector runs from the *versioned* keg `Cellar/vector/0.61.0`. rabbitmq's beam.smp runs from `Cellar/erlang/29.1.2`. grafana shows `started` with exit_code 1. Started services: etcd, grafana, loki, prometheus, rabbitmq, valkey.
3. **Brew never restarts upgraded services** — new code first starts unattended at next login/reboot.
4. **Casks:** plain `outdated` already includes stale auto_updates casks; `--greedy` entries are stale Caskroom metadata (ghostty bundle already 1.4.0); naming a cask bypasses auto_updates protection; brew **quits running apps by default** (`--no-quit` needed). 6. **Ollama listens on `*:11434`;** model tags are mutable via `/api/create`.
7. **Third-party taps:** 51–55 installed, but only **3 of 22** outdated formulae are from them (oh-my-posh, smartthings, vector).
8. **Rollback window today is zero:** no formula has >1 keg; casks keep one version; no `brew switch`.
9. ~~**Owner-behaviour evidence:** redis hand-pinned 2025-04-30, ~19 months stale (7.2.7 vs 8.10.3).~~ **Corrected by owner:** the redis pin is deliberate (keep redis installed while valkey runs in its place; a carryover from redis-insight use). ## Settled (unanimous or 4/5) — fold into DESIGN v1.1

**Pipeline / rules**
- Decision unit = **undirected connected component** of outdated packages from `runtime_dependencies` (after name validation); one held member holds the component; upgrade each component in one explicit `brew upgrade -- a b c`. Dry-run at most a cross-check. Drops bounded drop-iteration (C2).
- **Live-process set** = brew-services status ≠ none ∪ LaunchAgent/Daemon `ProgramArguments[0]` resolving (symlinks followed) into a formula's opt/Cellar/bin ∪ running executables there; plus their runtime-dep closure → HOLD; never clean their kegs; "upgraded, old binary still running" is an expected status (S2, S3).
- **Tap trust:** non-core tap ⇒ HOLD unless in `trusted_taps` (seed once at setup). **Soak:** auto-upgrade only versions first seen ≥ `min_age_days` (3) ago, for *all* packages, else DEFER (S1, D9).
- **Caveat diffing:** persist caveat hash at last upgrade; unchanged boilerplate ⇒ not a signal. Build before the model chain; size the chain from what's left (S10).
- No arm64 bottle ⇒ HOLD; `--` before package args; reject names with leading `-` or `..`; explicit-upgrade of a pinned pkg = pin conflict, not retryable (S11).
- Self-deps (fnox, the venv's python) reported, not upgraded in-run; "triage completes before apply" is a tested invariant (S12).
- Never set `HOMEBREW_NO_INSTALLED_DEPENDENTS_CHECK`; log `brew --version` per audit record.

**Model chain**
- **Drop self-reported confidence and the cap/threshold scheme.** Required boolean risk fields (mentions_migration, mentions_data_format, mentions_restart, mentions_manual_step, boilerplate_only), emitted *before* `verdict`, plus a coverage check (each present risk fact must be addressed). Fixed-outcome categories (unparseable, deprecated, high-dependent, live service) become rule HOLDs — zero model calls (D4, 5/5).
- **Local models classify caveats only; they may add risk, never remove it.** No local-model output can cause an upgrade (D5, 5/5). Deterministic `suspicious_text` flag ⇒ HOLD.
- Any L2 judges blind (facts only). `num_predict` cap (~400), truncated JSON ⇒ unsure, `think:false`.
- Pin model digests from `/api/tags`; mismatch ⇒ rules-only + warn; warn if Ollama bound off loopback (S6).
- Evaluation: ~25–30-case golden set (real caveats from this machine + dangerous + injection synthetics, run against real models), reuse the JSONL rather than a separate harness; shadow mode for the first ~10 runs; ship gate = 0 false approves on actionable + injection sets (S9, trimmed).

**State / reliability**
- Holds split **decided** vs **transient**; transient ones are excluded (not pinned) and retried every run; stamp records `quality: full|degraded` (S7).
- Ledger `pending_pin` written (0600) before `brew pin`; every run starts with reconcile vs `brew list --pinned` (tool record + unpinned ⇒ user released, don't re-pin that version; pin w/o record ⇒ user pin) (C7, S8).
- Dead-man alarm: `last_full_success` > 48 h surfaced by every invocation and by `status` exit code (S8).
- Hold aging: count, oldest age (decided holds only), blocked-by-dep count in every summary/`status`; stale holds escalate; weekly digest (C6).
- State dir 0700 / files 0600; refuse group/world-writable config; strip ANSI/control chars before printing; label model reasoning as derived from untrusted text; redact stderr tails in audit.

**Secrets / env**
- No `fnox exec` in the plist. Plist runs `.venv/bin/morning-brew` directly (installed via `uv sync --frozen`, not `uv run`). Claude key fetched lazily via `fnox get` (stdin=DEVNULL, 10 s timeout) only when L3 is reached, passed to the SDK, never in `os.environ`; child envs from an explicit allowlist with a test that notifier envs contain no `*KEY*`/`*TOKEN*` (C3).

**Scope**
- Casks **report-only** in v1 (5/5); S4 findings (`--no-quit`, DEFER running, widened installer/uninstall/flight HOLD rule) recorded as v1.1 design input.
- Cut OpenAI-compatible adapter (T24+S3), `OsaScriptNotifier`-as-escaping-surface concerns noted; README rollback procedure, no automated rollback (C1, C8).
- Scheduling: `StartInterval` 3600 + stamp + earliest-hour gate, no `RunAtLoad`; exit 75 is a log marker, not a retry mechanism (D7, 4/5; homebrew-ops preferred one calendar slot).
- Notifications: silent persistent macOS notification + status file by default; `say`/Hue for urgent/anomalies only; quiet hours; weekly holds-aging digest (D8, 5/5).

## Owner decisions (2026-11-17)
- **O1 → exclude, never pin.** "We don't generally pin anything." HOLD = excluded from the explicit upgrade list and recorded in the tool's ledger/status; the tool creates no pins. Existing user pins (redis) are SKIP and never touched. *(Designer's reading of the owner's answer; owner may correct.)* This removes pin-ownership machinery (pending_pin, unpin-on-release); reconcile reduces to "detect user pins".
- **O2 → Claude (L3) in v1, enabled even when Ollama is down.** fnox fetch failure ⇒ transient hold (retried), never a decided hold.
- **O3 → one local model** (qwen3:4b, caveat classification only). glm-4.7-flash dropped. Claude is the advisor.
- **O4 → deferred cleanup after 2 full successful runs**, never cleaning kegs in the live-process set.
